# 報告管理前端 — 實施計畫

> 這份文件是**施作交接文件**，寫給後續接手的人（或 AI session）。
> 讀完應該能在沒有前後文的情況下直接動工。
>
> 對應 [`ROADMAP.md`](ROADMAP.md) P1 的「HTML 報告輸出」。

## 要解決什麼問題

研究報告以 md 檔累積在 `reports/`，但沒有機器可讀的 metadata，所以**無法知道
哪份過期了、哪份還在追蹤、哪份重要**。目標是做一個網頁前端來查閱、篩選、追蹤
報告，並接上個人持倉資料，讓它成為真正的投資工具。

## 核心架構決策

### 一、不用資料庫，用「三層 metadata 合併」

md 檔永遠是唯一真相（single source of truth）。索引是可隨時重建的快取，刪掉不掉資料。

| 優先序 | 來源 | 誰維護 | 狀態 |
|---|---|---|---|
| 1（最高） | 報告內 YAML frontmatter | skill 自動寫入 / `add_frontmatter.py` 批次補 | ✅ 已完成 |
| 2 | `data/report-meta/overrides.json` | 人工標註 | ⬜ 階段 A |
| 3（最低） | 啟發式推導（檔名 → 表頭 → 兄弟檔 → git commit date） | `scripts/report_meta.py` | ✅ 已完成 |

這樣同時保有三種入口，缺一不可：

- **GitHub 上直接讀 raw md**——不需要任何部署
- **本機 `npm run dev`**——完整功能含個人財務
- **GitHub Pages**——公開網址，隨時查閱

用真資料庫會失去前兩項；純 md 資料夾則沒有查詢與追蹤能力。三層合併兩者兼得。

### 二、公開層與私密層分離

```
公開層 → GitHub Pages          私密層 → 只在本機 npm run dev
─────────────────────          ──────────────────────────
報告瀏覽 / 搜尋 / 追蹤          持倉 / 損益 / 資產配置
資料：reports/**.md            資料：local/userfin/**（已 gitignore）
```

同一份 codebase，用 `import.meta.env.DEV` 切開。**production build 不含個人模組的
程式碼，不只是不含資料**——Rollup 會把整個 `views/personal/` 從 bundle 剔除。

### 三、slug 路由繞開路徑地雷

報告路徑含中文、空格、`%`、書名號。**不改檔名**，改用兩層映射：

- 網址列：`#/r/{slug}` — 純 ASCII、可分享、可加書籤
- 內部：slug → 真實路徑 → 逐段 `encodeURIComponent()` 後 fetch

`make_slug()` 已實作於 `scripts/report_meta.py`，以路徑 sha1 前 6 碼收尾，保證唯一且冪等。

> 路由必須用 **hash mode**。GitHub Pages 沒有 SPA fallback，history mode 直接貼網址會 404。

## 階段 A：索引產生器

**前置條件：`reports/` 已有實際報告**，否則欄位設計與篩選維度都只是猜測。

新增 `scripts/build_report_index.py`，**直接 import `report_meta.py`**，不要重寫推導邏輯。

```python
import report_meta as rm
for path in rm.iter_reports():
    meta = rm.derive(path)     # 已含 date/company/type/ticker/review_by/status/slug
```

需要新增的部分：

1. **摘要與標題階層抽取**——H1 標題、前 200 字摘要、所有 H2/H3（供 TOC 與搜尋）、字數
2. **人工標註層** `data/report-meta/overrides.json`，路徑為 key，可只寫一部分：

   ```json
   {
     "reports/輝達/投研報告/20260426-安全墊分析.md": {
       "status": "active", "conviction": 5, "priority": "high",
       "review_by": "2026-10-01", "tags": ["核心持股"]
     }
   }
   ```

3. **實體字典** `data/report-meta/entities.json`——修正顯示名稱與分類，不改目錄名：

   ```json
   {
     "英伟达": { "display": "輝達", "en": "NVIDIA", "ticker": "NVDA",
                 "aliases": ["NVDA", "NVDA.US"], "kind": "company" },
     "投资方法论": { "display": "投資方法論", "kind": "topic" },
     "bottleneck-map": { "display": "瓶頸獵手訊號", "kind": "signal" }
   }
   ```

   `kind` 區分 `company` / `industry` / `topic` / `person` / `signal` / `pool`。

4. **訊號分流**——`bottleneck-map/` 底下的盤中訊號掃描標為 `kind: "signal"`，
   數量可能是投研報告的數倍，**不能混進預設清單**
5. **輸出** `web/public/index.json`，進 git，讓 clone 下來不跑 Python 也能用

順帶重跑 `python3 scripts/build_graph.py` 重新產生 `data/project_graph.json`
與 `docs/PROJECT_GRAPH.md`（PR #14 已刪除舊的過期產物）。

## 階段 B：前端

Vue 3 + Vite + TypeScript。環境已有 Node 22 / npm 10。倉庫目前**零前端、零 CI**。

```
web/
├── package.json      vue, vue-router, markdown-it, markdown-it-anchor,
│                     highlight.js, minisearch
├── vite.config.ts    base: '/ai-berkshire/'
├── public/index.json ← 階段 A 產物
└── src/
    ├── lib/          index.ts、filters.ts、markdown.ts、search.ts、paths.ts、tickers.ts
    ├── components/   FilterPanel、ReportCard、ReportTable、StatusBadge、
    │                 StarRating、TocSidebar、ThemeToggle
    └── views/        Dashboard、ReportList、ReportReader、CompanyPage、SignalTimeline
```

### 五個頁面

| 路由 | 內容 |
|---|---|
| `/` 儀表板 | 四張統計卡（總報告數／追蹤中公司／待複查／本月新增）；**「⚠️ 該複查了」置頂**；「⭐ 高信念標的」卡片牆（conviction ≥ 4）；「📅 最近更新」時間軸 |
| `/reports` 全報告 | 左側篩選（公司、類型、狀態、年份、大師視角、tag）＋ 表格／卡片切換；頂部即時搜尋（MiniSearch 比對標題＋標題階層＋摘要＋ticker）；欄位可排序 |
| `/r/:slug` 閱讀頁 | fetch md 即時渲染；右側浮動 TOC；表頭 metadata 卡（含「已 N 天未更新」）；上下篇導覽；「在 GitHub 上檢視」連結 |
| `/c/:entity` 公司頁 | 該公司報告時間軸＋依類型分組；ticker、報告數、最新研究日期 |
| `/signals` 訊號 | 瓶頸獵手掃描的日期軸視圖，依日期分組、可依 ticker 篩選、**需分頁** |

### 設計要點

- **深色模式**（`prefers-color-scheme` ＋ 手動切換，存 localStorage）
- **繁體中文排版**：`font-family` 優先 `"PingFang TC", "Noto Sans TC"`；行高 1.8；正文限寬 42em
- **不引入 UI 框架**，手寫 CSS variables，符合本專案零依賴的文化
- `vite-plugin-static-copy` 把 `reports/**/*.md` 複製進 `dist/`，讓 Pages 上的閱讀頁 fetch 得到

## 階段 D：UserFin 持倉聯動

UserFin 是本機獨立的網頁應用（`~/Workspace/UserFin`），涵蓋持倉損益、交易帳、
記帳預算、淨值追蹤。**本次只接「持倉」一片，不移植也不修改 UserFin。**

### 隱私邊界（三道防線）

1. **資料**只存在 `local/userfin/`——`.gitignore` 的 `/local/` 已涵蓋，不需新增規則
2. **建置產物**：個人模組只在 dev 模式存在，`npm run build` 的 `dist/` 不含個人程式碼也不含資料
3. **公開的映射檔** `entities.json` 只有 ticker ↔ 公司名對應，**沒有股數、成本、金額**

### 資料契約

`local/userfin/holdings.json`：

```json
{
  "as_of": "2026-08-22",
  "base_currency": "TWD",
  "holdings": [
    { "ticker": "NVDA", "name": "輝達", "market": "US", "currency": "USD",
      "shares": 120, "cost_basis": 142.30, "market_price": 186.50, "account": "IB" }
  ]
}
```

`market_price` 選填——沒有的話由既有的 `tools/ashare_data.py`、`tools/twstock_data.py` 補。
市值、未實現損益、組合權重全部在前端推導，不存進檔案。

同時提供 `local/userfin/holdings.sample.json`（假資料，**這一份進 git**）當 schema 範例，
讓開發與驗證不必依賴真實資料。另附 `scripts/validate_holdings.py` 檢查格式。

### Vite 如何讀到 `local/`

`local/` 在倉庫根目錄、`web/` 的上層，Vite 預設 serve 不到。用 **dev-only 中介層外掛**
（`vite.config.ts` 的 `configureServer`，設 `apply: 'serve'`）把 `local/userfin/` 掛到
`/__userfin/` 路由。

選這個而不是 symlink 或 `server.fs.allow`，是因為它在結構上保證 production build
碰不到這些檔案。

### 聯動功能

| 位置 | 功能 |
|---|---|
| 報告閱讀頁 | metadata 卡多一列持倉狀態：持有股數、成本、市值、佔組合 %、未實現損益 |
| 儀表板「待複查」 | 排序改為 **逾期天數 × 持倉權重**——重倉的東西過期才是真的急，而非單純按日期排 |
| 儀表板新增區塊 | **「持有但無研究」**警示：有持股卻找不到任何報告的標的。這是覆蓋率缺口，通常最有價值 |
| `/holdings`（dev only） | 每檔持股一列：權重、損益、最新研究日期、新鮮度徽章、報告數；點擊直達公司頁 |
| 公司頁 | 頂部顯示該標的持倉摘要 |

反向的「有研究但無持倉」自然構成觀察名單，在 `/reports` 用篩選器表達。

## 已知的坑（都是實際踩過的）

### git 對非 ASCII 路徑會加引號

`git ls-tree`／`git log` 預設把含中文的路徑輸出成 `"reports/英伟达/..."`（加引號、
非 ASCII 轉八進位跳脫）。規劃時因此把 713 份報告數成 120 份。

**任何 shell 呼叫 git 的地方都要加 `-c core.quotepath=false`。**
`report_meta.git_commit_date()` 已經這樣做了。

### 路徑地雷

實際存在過的：`reports/GE Vernova/`（空格）、`晨星深度低估/FICO-宽护城河-低估71%/`（`%`）、
`《看懂Meta》/`（書名號）。**逐段 `encodeURIComponent()`，不要對整條路徑用 `encodeURI`**
（後者不會處理 `%`）。

### 目錄名簡體、內文繁體

`d551c38` 把內文轉為繁體，但目錄與檔名仍是簡體。**不要為此大規模改名**——
用 `entities.json` 的 `display` 欄位做顯示映射，零風險、效果相同。

同理，`report_meta.MASTER_ALIASES` 已處理 `芒格`/`蒙格`、`李录`/`李錄` 的簡繁比對。

### `derive_company` 的限制

取 `reports/` 下的第一層目錄名。所以 `reports/晨星深度低估/Broadridge-宽护城河-低估69%/`
這種把公司放第二層的池狀目錄，會推導出 `晨星深度低估` 而非 `Broadridge`。

上傳時遵循 `reports/{公司}/...` 慣例即可避開，或在 frontmatter 直接指定 `company`。

### 已修正但值得知道的四個推導缺陷

端對端演練 50 份真實報告時抓到的，都已有迴歸測試護著：

1. **正文歷史年份被當成報告日期**——Meta 公眾號文因內文「2022 年 11 月，Meta 跌到
   90 美元」被判為 2022-11-01。修法：表頭日期只掃 metadata 行（`>` 或 `**` 開頭），
   且在第一條水平線處停止
2. **目錄語意輸給檔名**——`团队分析/02-财务估值分析-巴菲特视角.md` 被判成 `valuation`。
   修法：目錄優先於檔名
3. **`投研报告` 未被 `TYPE_RULES` 涵蓋**而落入 `other`
4. **`（NASDAQ: MRVL）` 這類帶交易所前綴的 ticker 抓不到**

## 施作順序建議

階段 A → B → C 是一條線，D 可以在 B 完成後平行進行。
建議拆成兩個 PR：**A＋B＋C**（公開的報告瀏覽）、**D**（個人財務聯動）。

前者能獨立上線產生價值，後者涉及隱私邊界，分開比較好驗證。
